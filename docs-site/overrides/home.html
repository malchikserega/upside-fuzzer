The pipeline

Three programs, one feedback loop

Loosely coupled and joined by files, HTTP and shared memory — each stage can be run, replaced or debugged on its own.

01

Instrument

fuzz-prep-multi.py · Cecil instrumentor

SharpFuzz rewrites every basic block of your published DLLs. A DOTNET_STARTUP_HOOKS assembly links coverage at load time — no edits to Program.cs, Startup.cs or .csproj.

  • AFL-style hit-count buckets, auto-sized bitmap
  • CmpLog: magic values from the target’s own comparisons
  • Constant dictionary harvested from IL

02

Compile grammar

grammarc · Roslyn analyzer

A first-party OpenAPI 2/3 compiler (no RESTler) produces typed request templates. The optional Roslyn pass reads the real [Range], [StringLength], enum and FluentValidation rules per type and property.

  • Producer → consumer id inference
  • Boundary values: min−1, min, max, max+1
  • dict.custom.json for your own values

03

Fuzz with void

Go engine · src/void

Energy-scheduled seeds, MOpt-weighted mutation, stateful request chains over a typed resource-lifecycle graph, and security oracles replaying every success under other identities.

  • Fail-closed warm-up coverage probe
  • Triage tiers, root-cause clustering, repro + PoC
  • SARIF with run manifest and chain trace

Oracles

The worst API bugs return 200 OK

A crash says the code is fragile. It says nothing about whether another tenant can read your invoices. The oracles below run alongside ordinary fuzzing and look for bugs that crash-only fuzzers structurally cannot see.

Access control

BOLA / IDOR

Successful requests replayed under every other identity; identical or foreign data coming back is flagged.

bola_identical_cross_identity_response
Access control

Broken authentication

No-credential replay, only on endpoints already proven to enforce auth — no public-endpoint noise.

auth_bypass_unauthenticated_access
Access control

Differential auth bypass

Verb swap, content-type confusion, route-case and param-location tricks.

differential_auth_bypass:<technique>

Scheduling

Five epochs, rebalanced while it runs

The time budget is split into epochs. An epoch that stops finding new edges loses part of its budget to Havoc; seeds that reach new code earn energy, with a bonus for the first new edge after a long drought.

Stateful

Workflows, not single requests

A POST that creates an invoice feeds its real id into GET/PUT/DELETE follow-ups. A typed resource graph tracks each object’s lifecycle, and a never-seen workflow shape earns extra budget.

  1. POST/api/projects/{id}/tasks 201 · id=412
  2. POST/api/tasks/412/submit-for-review 200 · in_review
  3. DELETE/api/tasks/412 204 · deleted
  4. PUT/api/tasks/412 200 · stale_object

Illustrative chain. Crashes reached through chains are minimized as whole chains and exported with producer → consumer bindings.

git clone {{ config.repo_url }}.git

# 1 · instrument (zero-edit) and start
python3 bin/fuzz-prep-multi.py --src ./my-project --out ./my-project-fuzz --main MyProject.Api
(cd my-project-fuzz && docker compose build && docker compose up -d)
# 2 · verify coverage is live
curl -s http://localhost:8080/shm/health
# 3 · compile the grammar
./bin/compile-grammar.sh swagger.json --src ./my-project
# 4 · fuzz
docker compose --profile fuzz-go run --rm void \
  -grammar grammars/my-project -auth-file ./auth.identities.json \
  -direct-shm -profile security -time-budget 60
